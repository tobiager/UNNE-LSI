MODELO PACKET TRACER - RELEVAMIENTO DGI PODER JUDICIAL DE CORRIENTES
Redes de Datos - UNNE FaCENA - 2026 - Grupo 5
============================================================================

ARCHIVO: Modelo_DGI_PoderJudicial.pkt (Packet Tracer 9.0.1.0858) - 33 equipos, 37 enlaces.
Es el modelo unificado del grupo: combina el modelo reducido de topologia Cisco
(VLAN por funcion del datacenter, VTP, servidor publico vs privado, localidades
remotas con DHCP) con la redundancia relevada (dos firewalls con HSRP, dos ISP,
cores con EtherChannel, accesos con doble uplink, WAN MPLS simulada).

COMO ABRIRLO
1. Abrir el .pkt en Packet Tracer 9.0.1 o superior.
2. Esperar ~1 minuto (o "Fast Forward Time" varias veces) para que converjan
   OSPF, STP, HSRP, EtherChannel, VTP y DHCP.
3. Si algun equipo aparece sin configuracion (por ejemplo en otra version de PT):
   enable / copy startup-config running-config, o pegar su bloque de la seccion
   CONFIGURACIONES y luego "write memory". Contrasena de enable: DGIpj2026
   (la consola no pide contrasena; el acceso remoto es solo SSH con usuario admin).

EQUIPOS POR SITIO
  Internet .......... ISP1, ISP2 (2911), SW-INTERNET, SRV-INTERNET (web + DNS), PC-EXTERNO
  Datacenter ........ FW1-DGI y FW2-DGI (2911: firewall/borde con HSRP, NAT, ACL)
                      SW-DC-CORE1 / SW-DC-CORE2 (2960, EtherChannel LACP, VTP server/cliente)
                      SW-DC-ACC1 / SW-DC-ACC2 (2960, doble uplink a ambos cores)
                      SRV-PRIVADO (AD/DNS), SRV-PUBLICO (web), SRV-PREPROD, SRV-LAB
                      PC-ADMIN, PC-USUARIO, PC-WIFI
  Capital (campus) .. SW-TRIBUNALES + PC (enlace de fibra propia desde CORE2)
                      SW-EDIF-RADIO + PC (radioenlace desde CORE1, modelado como Ethernet)
  WAN MPLS .......... PE-CAPITAL, PE-GOYA, PE-STOME (routers del proveedor, OSPF area 0)
  Goya .............. R-GOYA (DHCP), SW-GOYA, PC-GOYA-ADM, PC-GOYA-USR
  Santo Tome ........ R-STOME (DHCP), SW-STOME, PC-STOME-ADM, PC-STOME-USR

SIMPLIFICACIONES RESPECTO DE LA RED REAL (decirlo en la defensa)
  - Los FortiGate se representan con routers 2911 (NAT, ACL, HSRP). PT no tiene FortiGate.
  - 4 ISP reales -> 2 en el modelo. 36 localidades -> 2 (Goya y Santo Tome).
  - La MPLS de Telecom se simula con 3 routers PE en OSPF area 0; los tuneles IPsec no se modelan.
  - El stack de cores Aruba se representa con 2 switches 2960 unidos por EtherChannel LACP.
  - El radioenlace y la fibra entre edificios de Capital se modelan con cables Ethernet.
  - 802.1X no esta disponible en los switches de PT; se usa port security + BPDU guard.
  - Wi-Fi: se representa con una PC en la VLAN 10 (sin access point).

PRUEBAS (capturar pantalla de cada una para el informe)
  P1 DHCP y alcance WAN: PC-GOYA-USR > IP Configuration = DHCP -> toma 10.2.60.x.
     Web Browser -> http://www.pjcorrientes.gob.ar (10.0.40.10) y ping 10.0.30.10.
  P2 NAT a Internet: PC-STOME-USR (DHCP) -> Web Browser www.internet.com.
     En FW1: show ip nat translations
  P3 Servidor publico vs privado: PC-EXTERNO -> Web Browser http://www.pjcorrientes.gob.ar
     (resuelve 200.1.1.5, NAT estatico hacia SRV-PUBLICO) responde. ping 10.0.30.10 falla:
     los servidores privados no se publican.
  P4 Redundancia de salida (HSRP + OSPF): FW1 "show standby brief" (Active).
     PC-USUARIO: ping -t 200.0.0.10. Apagar ISP1 G0/0. FW2 pasa a Active (track G0/0)
     y el ping se recupera por ISP2. En PE-CAPITAL: show ip route 0.0.0.0
  P5 Segmentacion: PC-USUARIO ping 10.0.50.10 -> falla (ACL PROTEGE-ADMIN);
     PC-ADMIN ping 10.0.60.10 -> responde. PC-WIFI y SRV-LAB ping 10.0.30.10 -> fallan
     (ACL PROTEGE-PRIVADOS). show access-lists en FW1.
  P6 EtherChannel: SW-DC-CORE1 show etherchannel summary (Po1 SU). Quitar el cable
     Gi0/1 entre cores: PC-ADMIN sigue respondiendo.
  P7 Doble uplink (RSTP): SW-DC-ACC2 show spanning-tree vlan 50 (Fa0/24 alternativo).
     Apagar Fa0/23 en ACC2: Fa0/24 pasa a forwarding y el servicio sigue.
  P8 Ruteo y VTP: R-STOME show ip ospf neighbor / show ip route ospf (redes 10.x y O*E2).
     SW-DC-ACC1 show vtp status (dominio dgi-corrientes, VLANs aprendidas de CORE1).

#### 1.4 – Modelos de referencia OSI e Internet.


```
⚫ Una capa de protocolo se puede implementar en software, en hardware o en una
combinación de los dos.
```
```
⚫ Los protocolos de capa de aplicación, como HTTP y SMTP, casi siempre se implementan
en software en los sistemas finales; como también los protocolos de la capa de
transporte.
```
```
⚫ Debido a que la capa física y las capas de enlace de datos son responsables de manejar
la comunicación a través de un enlace específico, generalmente se implementan en una
tarjeta de interfaz de red (por ejemplo, tarjetas de interfaz Ethernet o WiFi) asociadas
con un enlace dado.
```
```
⚫ La capa de red es a menudo una implementación mixta de hardware y software.
```
#### 1.4 – Modelos de referencia OSI e Internet.


```
⚫ La estratificación en capas de protocolo tiene ventajas conceptuales y estructurales [RFC
3439]. La estratificación proporciona una forma estructurada de analizar los
componentes del sistema. La modularidad facilita la actualización de los componentes
del sistema.
```
```
⚫ Algunos investigadores e ingenieros de redes se oponen con vehemencia a la
estratificación [Wakeman 1992]. Un posible inconveniente de la estratificación es que
una capa puede duplicar la funcionalidad de la capa inferior.
```
```
⚫ Por ejemplo, muchas pilas de protocolos proporcionan recuperación de errores tanto
por enlace como de extremo a extremo. Un segundo inconveniente potencial es que la
funcionalidad en una capa puede necesitar información (por ejemplo, un valor de
tiempo) que está presente solo en otra capa; Esto viola el objetivo de separación de
capas.
```
```
⚫ Es posible acomodar protocolos de diversas capas en una “pila de protocolos”. La pila de
protocolos de Internet consta de cinco capas: las capas física, de enlace, de red, de
transporte y de aplicación.
```
#### 1.4 – Modelos de referencia OSI e Internet.


```
⚫ Un protocolo de capa de aplicación se distribuye en múltiples sistemas finales, con la
aplicación en un sistema final utilizando el protocolo para intercambiar paquetes de
información con la aplicación en otro sistema final. Entendemos a este paquete de
información en la capa de aplicación como un mensaje.
⚫ La capa de transporte de Internet transporta los mensajes de la capa de aplicación
entre los puntos finales de la aplicación.
⚫ En Internet hay dos protocolos de transporte, TCP y UDP, cualquiera de los cuales puede
transportar mensajes de la capa de aplicación.
⚫ TCP proporciona un servicio orientado a la conexión a sus aplicaciones, que incluye la
entrega garantizada de mensajes de la capa de aplicación al destino y al control de flujo
(es decir, coincidencia de velocidad del emisor / receptor). Divide los mensajes largos en
segmentos más cortos y proporciona un mecanismo de control de congestión, de
modo que una fuente limita su velocidad de transmisión cuando la red está
congestionada.
⚫ UDP proporciona un servicio sin conexión a sus aplicaciones. Este es un servicio sencillo
que no proporciona confiabilidad, control de flujo ni control de congestión.
⚫ En general, nos referimos a un paquete de capa de transporte como un segmento.
```
#### 1.4 - Modelos de referencia OSI e Internet.


⚫ La **capa de red** de Internet es responsable de mover los paquetes de capa de

###### red conocidos como datagramas de un host a otro.

```
⚫ El protocolo de capa de transporte de Internet (TCP o UDP) en un host de origen
pasa un segmento de capa de transporte y una dirección de destino a la capa de
red.
⚫ Proporciona el servicio de entregar el segmento a la capa de transporte en el
host de destino.
⚫ El Protocolo IP, define la estructura del datagrama y el comportamiento de los sistemas
finales y los enrutadores. Los dispositivos de Internet que tienen una capa de red
deben ejecutar el protocolo IP.
⚫ Contiene protocolos de enrutamiento que determinan las rutas que toman los
datagramas entre orígenes y destinos.
```
#### 1.4 - Modelos de referencia OSI e Internet.


```
⚫ Para mover un paquete de un host o enrutador al siguiente en la ruta, la capa de red se
basa en los servicios de la capa de enlace.
⚫ En particular, en cada host, la capa de red pasa el datagrama a la capa de enlace, que
entrega el datagrama al siguiente host a lo largo de la ruta.
⚫ En este siguiente host, la capa de enlace ‘sube’ el datagrama a la capa de red.
⚫ Los servicios proporcionados por la capa de enlace dependen del protocolo específico
que se emplea a través del enlace.
⚫ Por ejemplo, algunos protocolos de capa de enlace proporcionan una entrega
confiable, desde el host de transmisión, a través de un enlace, hasta el host de
recepción.
⚫ Los ejemplos de protocolos de capa de enlace incluyen Ethernet, WiFi y el protocolo
DOCSIS de la red de acceso por cable.
```
#### 1.4 - Modelos de referencia OSI e Internet.


```
Los datagramas generalmente necesitan atravesar varios enlaces para viajar de origen a
destino, pueden ser manejados por diferentes protocolos de capa de enlace en diferentes
enlaces a lo largo de su ruta.
⚫ Por ejemplo, un datagrama puede ser manejado por Ethernet en un enlace y por PPP en
el siguiente enlace.
⚫ La capa de red recibirá un servicio diferente de cada uno de los diferentes protocolos
de capa de enlace.
⚫ Nos referimos a los paquetes de capa de enlace como frames.
⚫ El trabajo de la capa física es mover bits individuales dentro del frame de un host al
siguiente. Los protocolos en esta capa dependen nuevamente del enlace y dependen aún
más del medio de transmisión real del enlace (por ejemplo, cable de cobre de par
trenzado, fibra óptica monomodo).
```
```
⚫ Ethernet tiene muchos protocolos de capa física según las capacidades. En cada caso,
un bit se mueve a través del enlace de una manera diferente.
```
#### 1.4 - Modelos de referencia OSI e Internet.


```
⚫ INTERNET no es la única pila de protocolos disponible. A fines de la década de 1970, la Organización
Internacional de Normalización (ISO) propuso que las redes de computadoras se organizaran en
torno a siete capas, denominado modelo de interconexión de sistemas abiertos (OSI).
⚫ El modelo OSI tomó forma cuando los protocolos que se convertirían en protocolos de Internet
estaban en su infancia, y no eran más que uno de los muchos conjuntos de protocolos diferentes en
desarrollo; de hecho, los inventores del modelo OSI original probablemente no tenían en mente
Internet al crearlo. El modelo de siete capas continúa persistiendo en algunos libros de texto y cursos
de capacitación.
⚫ La funcionalidad de cinco de estas capas es aproximadamente la misma que la de sus homólogos de
Internet con nombres similares. Las dos capas adicionales presentes en el modelo de referencia OSI:
la capa de presentación y la capa de sesión.
⚫ Capa de presentación : proporcionar servicios que permitan que las aplicaciones en comunicación
interpreten el significado de los datos intercambiados. Estos servicios incluyen la compresión de
datos y el cifrado de datos, la descripción de datos, que libera a las aplicaciones de tener que
preocuparse por el formato interno en el que se representan o almacenan los datos, formatos que
puede diferir de una computadora a otra.
⚫ Capa de sesión : proporciona la delimitación y sincronización del intercambio de datos, incluidos
los medios para construir un esquema de recuperación de puntos de verificación.
```

⚫ **¿Cómo puedo corregir un error en un RFC publicado?**

```
⚫ ¡No se puede! Una vez que se publica un RFC, no se puede cambiar. Los RFC forman una
serie de archivos. Si el error representa un cambio de contenido, se puede escribir un
RFC revisado que quede obsoleto por error. Para informar un error en un RFC, utilice el
formulario disponible en la página de erratas de RFC
```
⚫ **¿Puedo recibir una notificación cuando se publique un nuevo RFC?**

```
⚫ Sí. Se envía un anuncio de cada nuevo RFC a todos los miembros de la lista de correo
rfc-dist. Puede suscribirse y darse de baja de esta lista en http://www.rfc-
editor.org/mailman/listinfo/rfc-dist
```
⚫ **¿Cuánto tiempo tarda un documento en convertirse en un RFC?**

```
⚫ El tiempo típico de publicación es de 1-2 meses, pero el tiempo real varía
mucho de un RFC a otro. La publicación puede demorarse por una variedad de
razones, incluida la aprobación de IESG.
```
